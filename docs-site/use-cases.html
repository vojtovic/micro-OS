Use Cases

Practical workflows this current firmware supports today.

1) Bring-up bench diagnostics

Validate that board buses and key peripherals are alive after wiring or board revision changes.

devls -v
i2cdetect
lsblk
df
watchdog status

2) On-device file management

Use Linux-style commands to inspect, create, and mutate files directly on the SD card.

cd /sdcard
mkdir lab
write lab/readme.txt hello micro_arch
append lab/readme.txt second line
cat lab/readme.txt
tree /sdcard

3) Persistent operational logging

Capture lightweight notes on internal flash for debugging sessions that survive reboots.

note started thermal run
note fan pwm set to 30 percent
note

Notes are stored at /sys/log/notes.log.

4) Boot automation

Execute a deterministic startup routine from /sdcard/etc/init.conf.

write /sdcard/etc/init.conf echo boot profile A
append /sdcard/etc/init.conf devls
append /sdcard/etc/init.conf df

Commands run automatically on boot when SD mount succeeds.

5) Hardware probing and smoke tests

gpio mode 4 out
gpio write 4 1
sleep 0.2
gpio write 4 0
beep 1200 150
i2cget 0x5F 0x00 1

6) Runtime service and config inspection

service list
service info klog
fstab
vconsole status
vconsole tail 20
config /sdcard/etc/hardware.conf
config /sdcard/etc/hardware.conf buzzer.pin

Use this to verify registered services and quickly inspect INI configuration values from the shell.
