Getting Started

Set up your local toolchain and reach the interactive shell on your ESP32-S3 device.

Prerequisites

  • ESP32-S3 board (configured in platformio.ini as freenove_esp32_s3_wroom)
  • PlatformIO CLI installed
  • USB serial connection to your board

Build, flash, and monitor

cd /path/to/micro_arch
pio run
pio run -t upload
pio device monitor -b 115200

Project defaults:

  • Framework: ESP-IDF
  • Flash size: 16 MB with custom partition table (partitions_16MB.csv)
  • Monitor speed: 115200

Expected boot sequence

  1. Kernel log ring buffer is initialized.
  2. Boot beep plays on buzzer pin.
  3. PSRAM info is printed.
  4. Virtual console ring buffer initializes in PSRAM.
  5. Internal LittleFS mounts at /sys.
  6. Default /sys/etc/fstab is created if missing.
  7. SPI and I2C buses initialize.
  8. Filesystems are mounted from fstab entries.
  9. Filesystem skeleton is ensured under /sdcard.
  10. Service registry is initialized and core services are registered.
  11. Shell commands are registered and prompt starts.

First commands to run

help
uname
devls -v
fstab
vconsole status
service list
lsblk
df
pwd
ls

Expected output samples

Exact values will differ by board and storage, but output should look similar to this:

[/sdcard] uarch> uname

[/sdcard] uarch> devls -v

Common errors and what to do

Error / symptomWhat to do
SD mount failed during bootCheck SD card insertion, FAT formatting, SD wiring (CLK/MOSI/MISO/CS), then run mount manually and inspect devls -v.
PSRAM not detectedVerify board target in platformio.ini, then reboot and re-check with mem/free. If still missing, verify hardware/board variant.
Unknown commandRun help and use exact command names from command reference.
Cannot open / Not foundCheck current directory with pwd, list files with ls, and use absolute paths (/sdcard/... or /sys/... ).
rmdir ... (Permission denied)Directory is usually not empty. Check with ls/tree, remove files first (rm), then run rmdir again.
Cannot load: ... from configConfig file path does not exist or cannot be opened. Verify with pwd + ls, then use absolute path.
No response from I2C deviceRun i2cdetect. If address (e.g. 0x5F) is missing, check power, SDA/SCL pins, and pull-ups.
Filesystem seems inconsistent after power lossUse shutdown for clean unmount/restart and run sync to inspect mount/write status before reset.
