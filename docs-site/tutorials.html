Detailed Tutorials

Hands-on guides for common operator and developer tasks.

Tutorial 1: First successful boot session

  1. Build and flash firmware.
  2. Open serial monitor at 115200.
  3. Wait for prompt [...] uarch>.
  4. Run baseline checks: 
    help
uname
uptime
devls -v
lsblk
df
  5. Confirm both /sys and /sdcard are visible when expected.

Expected result: prompt is responsive, devls -v reports sd0 mounted (if SD inserted), and lsblk shows internal + sd0.

Tutorial 2: Create a maintenance workspace on SD

  1. Move to SD root: 
    cd /sdcard
pwd
  2. Create structure: 
    mkdir ops
mkdir ops/reports
mkdir ops/scripts
  3. Write and inspect report: 
    write ops/reports/session.txt micro_arch field test run 1
append ops/reports/session.txt bus healthy
cat ops/reports/session.txt
wc ops/reports/session.txt
  4. Audit tree and storage: 
    tree ops
du ops
df

Expected result: directory /sdcard/ops exists, session.txt contains two lines, and du ops reports non-zero usage.

Tutorial 3: Script repeatable diagnostics

  1. Create script file: 
    write /sdcard/tmp/diag.scr echo --- diag start ---
append /sdcard/tmp/diag.scr uptime
append /sdcard/tmp/diag.scr free
append /sdcard/tmp/diag.scr devls
append /sdcard/tmp/diag.scr i2cdetect
append /sdcard/tmp/diag.scr echo --- diag end ---
  2. Run it: 
    source /sdcard/tmp/diag.scr
  3. Inspect captured shell output: 
    vconsole tail 30
  4. Measure execution time: 
    time source /sdcard/tmp/diag.scr

Expected result: source executes all commands in order, vconsole tail shows recent output lines, and time ... prints a real X.XXX s line.

Tutorial 4: Configure boot automation with init.conf

  1. Prepare boot command list: 
    write /sdcard/etc/init.conf echo boot-sequence started
append /sdcard/etc/init.conf devls
append /sdcard/etc/init.conf df
append /sdcard/etc/init.conf note boot script executed
  2. Reboot: 
    reboot
  3. After restart, verify side effects: 
    note
dmesg

Expected result: after reboot, commands from /sdcard/etc/init.conf run automatically and their effects are visible in dmesg / note.

When a tutorial step fails

  1. Run pwd and ls to confirm you are in the expected path.
  2. Run devls -v to check storage and bus readiness.
  3. If SD-related command fails, run mount and retry the step.
  4. If command is not recognized, run help and verify syntax.
  5. Capture logs with dmesg and include the failing command + output in your issue notes.
