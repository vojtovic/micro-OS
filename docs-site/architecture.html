Architecture

Current runtime structure from the implemented firmware (foundation phase).

Boot flow

app_main
  -> klog_init()
  -> init_boot_beep()
  -> vconsole_init(32768)      // PSRAM virtual console ring
  -> internal_fs_mount()       // /sys (LittleFS)
  -> init_create_default_fstab()
  -> bus_init()                // SPI + I2C
  -> init_mount_fstab()        // mount from /sys/etc/fstab
  -> fallback storage_sd_mount() if /sys unavailable
  -> init_filesystem()         // ensure /sdcard hierarchy + default files
  -> registry_init()           // runtime service registry
  -> registry_add(...)         // klog, bus, internal_fs, vconsole, storage
  -> shell_init()              // register command groups
  -> init_run_bootscript()     // /sdcard/etc/init.conf (if SD mounted)
  -> shell_start()

Storage model

  • /sys: internal LittleFS partition named internal
  • /sdcard: external FAT filesystem (SPI SD card)

On first boot with SD mounted, the firmware ensures:

/sdcard/bin
/sdcard/drivers
/sdcard/etc
/sdcard/home
/sdcard/tmp
/sdcard/var/log

Boot-time config files

  • /sys/etc/fstab — filesystem mount table used at boot
  • /sdcard/etc/hardware.conf — pin/config placeholders for modules
  • /sdcard/etc/hostname — default hostname string
  • /sdcard/etc/init.conf — shell commands executed during boot

Bus layer

  • SPI3 bus initialized for SD card
  • I2C0 initialized at 100kHz
  • Helper API exposes SPI device add and bus lock/unlock for future modules

Shell subsystem

  • Based on esp_console
  • Prompt format: [cwd] uarch>
  • Tracks current working directory and command history (32 entries)
  • Normalizes relative paths (., ..) through shell path resolver
  • Registers base shell commands + file/system/diag + config + service + vconsole + fstab groups

Output channels

  • klog: captures ESP_LOG* output in a ring buffer (dmesg command).
  • vconsole: captures shell-visible output in a PSRAM ring buffer and mirrors to UART (vconsole command family).
